# 历史窗口查询与目录菜单（2026-09-30）

## 原因与实现

`cm ls --xml` 原生提供每个加载项的 Changeset、RevId、ItemId，但目录的版本不是“所有后代均已更新到此版本”的水位。在 TestSCM 的 Gluon 工作区中，根目录 Changeset 为 0，子项已经包含后续版本。因此继续按实际加载项及提交祖先关系判断未拉取状态，不能简单比较目录版本号或提交编号大小。

参考：[Unity Version Control CLI / LIST](https://docs.unity.com/en-us/unity-version-control/uvcs-cli/list)。本机 `cm help diff` 也确认单个 changeset 的 diff 是与其真实父提交的比较。

- 本地状态每次刷新或重新激活时读取；复用同次 status 响应确定当前分支，去掉重复 status。历史行在后台批量判断，完成后统一更新字体。修复目录已移动、旧路径子项尚未更新时的误判，包含从目标子路径查看历史的情况。
- Gluon 修订身份按最多 128 项一批查询。140 个未解析身份的回归用例仅需 2 次查询。
- 文件明细复用历史列表已经取得的提交元数据，以及黑体/路径历史使用的同一份 diff。无需再次 find changeset。大量文件的 ListView 使用 BeginUpdate/EndUpdate。
- Ctrl+D 复用单提交 diff，查询真实父提交后作为该父子对的比较依据；保持移动目录下文件的旧路径归一化和新增/删除空端点验证。两端下载并行，全部任务结束后才清理临时文件。
- 同一 PlasticClient 中缓存固定历史查询与比较文件内容。查询缓存最多 128 项、400 万字符；文件内容缓存最多 64 项、16 MiB，单文件最多 4 MiB。大文件仍按需下载。工作区状态和分支头不缓存，不写入永久的“已读/已下载”标记。
- 当前使用的经典 Explorer 菜单在单个受控工作区目录或目录空白处显示四个一级项：更新、签入、历史记录、TortoiseSCM。前三项从子菜单移除；命令编号、图标、原有文件及多选菜单行为保留。可选 Windows 11 现代菜单未改动。

## 验证

对同一 TestSCM 工作区的 1,040 条历史进行只读检查，改前和改后均得到 3 条未拉取记录。单次测量受进程启动、网络及服务器缓存影响，不作为性能保证。

| 操作 | 测量 |
| --- | --- |
| 改前首次快照和完整历史检查 | 14,349 ms |
| 改后首次快照和完整历史检查 | 11,641–12,115 ms |
| 改后重新激活：新本地快照和已有历史黑体计算 | 1,511 ms |
| 已取得的提交明细重复读取 | 0–2 ms |
| 首次真实父版本比较准备（已取得明细） | 336 ms |
| 同一父版本比较准备再次执行 | 1 ms |

上述比较准备时间不含外部比较工具启动。首次查询仍需要服务器；首次全历史扫描继续使用有界分页，以保留完整路径发布历史、回滚和祖先目录事件。

验证包括：历史分页、原生预览、混合版本黑体、140 项批查询、缓存后本地状态变化、Ctrl+D/双击/标记比较 UI、取消及仓库切换、比较对象伪造、目录与文件菜单、受限命令 ID、生产 DLL 命令派发。重复历史文件比较的测试确认第二次无需启动任何 cm 进程。

实际服务器测试使用独立 `/main/tortoisescm-autotest-integration-20260930-011805-2c4754c8` 分支，验证分别更新两个文件、卸载/重新加载、移动和删除；未切换原 TestSCM 的选择器。真实 Beyond Compare 窗口验证 `/ignore.conf` 的 cs:3 与 cs:4，核对两侧字节、只读输入、关闭及清理。已查看历史窗口正常与最小尺寸截图。
